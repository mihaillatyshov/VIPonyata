# Правила работы ИИ-агента

Только для ИИ-ассистентов (Claude Code и т.п.). Общая документация — в `docs/`.

## Перед началом задачи

1. Определи, какая часть затронута: `server/`, `client/` или обе. Прочитай соответствующий `CLAUDE.md` и `docs/<part>/architecture.md`.
2. Незнакомые термины (lexis, drilling, assessment, final_boss, quizlet, subgroup, task bank, homework, review) — в [../domain.md](../domain.md).
3. Проверь, нет ли связанного пункта в `docs/server/improvements.md` / `docs/client/improvements.md` — не усугубляй известную проблему, а если исправляешь её — обнови документ.

## Где что искать

| Нужно | Где |
|---|---|
| URL эндпоинта → хендлер | `server/server/routes/routes.py` (поиск по пути), затем `handlers/<role>/` |
| SQL/ORM-запрос | `server/server/queries/{Teacher,Student,Other,Review}DBqueries.py` |
| Таблица/колонка | `server/server/models/db_models.py` (`__tablename__`) |
| Схема запроса | `server/server/models/<feature>.py` (Pydantic) |
| Типы заданий assessment | `server/server/models/assessment.py` + `client/src/models/Activity/Items/TAssessmentItems.ts` |
| Страница клиента по URL | `client/src/App.tsx` → компонент |
| Тип ответа API на клиенте | `client/src/models/T*.ts` |

Кодовая база большая, а файлы длинные (до 2600 строк): ищи через Grep по имени эндпоинта/функции и читай нужный диапазон, а не весь файл.

## При изменениях

- **Изменение API** = сервер (Pydantic-модель, хендлер, роут) + клиент (тип в `models/`, вызов). Сохраняй обратную совместимость, если не просили иначе: клиент и сервер деплоятся одновременно, но у пользователей может быть открыта старая вкладка.
- **Изменение схемы БД** = правка `db_models.py` + миграция Alembic с осмысленным `upgrade`/`downgrade`. Автогенерацию нельзя применить без БД — если её нет, пиши миграцию вручную по образцу `migrations/versions/*`, `down_revision` = текущая голова (посмотри `grep -h "^revision\|^down_revision" migrations/versions/*.py`).
- Данные в JSON-колонках (`tasks`, `done_tasks`, `checked_tasks`, `task_json`, `queue_state`) уже лежат в проде — меняя формат, поддержи чтение старого.
- Проверки доступа: ученик не должен получать чужие данные и ответы к заданиям. Любой новый student-хендлер проверяет принадлежность ресурса текущему пользователю.
- Пользовательские тексты и сообщения ошибок — на русском, в стиле существующих.
- Не трогай стиль/форматирование несвязанного кода и не делай массовых переименований (опечатки вроде `cheked`, `hyeroglyph` — часть формата данных).
- Не добавляй код в файлы-гиганты — создавай соседний модуль/компонент.

## Проверка перед сдачей

Сервер (из `server/`, venv `server/.venv`):
- `.venv/Scripts/python -m py_compile <изменённые файлы>` — минимум;
- юнит-тесты assessment, если трогал `models/assessment.py` или автопроверку (команда в [../development.md](../development.md#тесты));
- `.venv/Scripts/python -m mypy server` — сейчас ~234 старые ошибки; сравни количество до/после, новых быть не должно.

Клиент (из `client/`):
- `npm run lint` — обязателен (его гоняет CI);
- `npx tsc --noEmit` — сейчас в проекте ~34 старые ошибки; сравни количество до/после, новых быть не должно;
- `npm run build` при изменениях конфигурации/зависимостей.

Сервер MySQL и `config_test.json` локально могут отсутствовать — тогда интеграционные тесты не запускаются; честно сообщи об этом, не утверждай, что всё проверено.

## Окружение

- Windows, основная оболочка PowerShell, есть Git Bash. Файлы TS — CRLF (prettier `endOfLine: crlf`).
- `server/requirements.txt` в кодировке UTF-16 LE — при правке сохраняй кодировку или (по согласованию) конвертируй в UTF-8.
- Не коммить и не пушить без явной просьбы: push в `master` сразу деплоит на прод.
- Коммиты в репозитории пишутся по-русски, коротко, в прошедшем времени («добавила ...», «фикс ...»).
